# 훈민정음21 (HMJE21) — 웹 재제작 설계서

> 기준: 원본 HTML v2.2 → Unity 포팅본(2026-11-25 분석 문서)을 바탕으로 웹(TypeScript + Three.js)으로 처음부터 다시 만든다.
> 이 문서는 Fusion(HEAD·BUILDER·REVIEWER)이 작업 명세를 만들 때 기준으로 삼는 문서다. 규칙을 바꿀 때는 이 문서를 먼저 고친다.

---

## 1. 컨셉

**"한글은 소리의 좌표계다."**

초성 19개, 중성 21개, 종성 28개(받침 없음 포함)를 3D 좌표축으로 놓으면, 현대 한글 음절 11,172자는 모두 공간의 한 점이 된다.
플레이어는 글자를 타이핑하거나 다이얼로 좌표를 맞춰 쏘면서 한글의 자모 구조와 조합 원리를 몸으로 익힌다.

- **대상:** 한글을 배우는 외국인 학습자. 자모 조합 원리를 직관적으로 이해하고 싶은 사람.
- **학습 순서:** 자모 → 받침 없는 음절 → 받침 있는 음절 → 단어 → 직접 좌표 찾기
- **격파 보상:** 글자가 폭발할 때 영어 뜻이 뜬다.

## 2. 좌표계 (확정)

> **결정 (2026-11-25):** X = 초성, **Y = 중성**, **Z = 종성**.
> Unity 포팅본의 `HangulUtils`(Y = 종성, Z = 중성)와 **반대**다. 옛 코드를 옮겨 올 때 축을 바꿔야 한다.

| 축 | 자모 | 개수 | 인덱스 | 색 |
|---|---|---|---|---|
| X | 초성 | 19 | 0~18 | 빨강 `#ff4d5e` |
| Y | 중성 | 21 | 0~20 | 시안 `#2ee6e6` |
| Z | 종성 | 28 | 0~27 (0 = 받침 없음) | 노랑 `#ffd23f` |

### 2-1. 자모 순서 (유니코드 표준 순서, 바꾸지 않는다)

- **초성(19):** ㄱ ㄲ ㄴ ㄷ ㄸ ㄹ ㅁ ㅂ ㅃ ㅅ ㅆ ㅇ ㅈ ㅉ ㅊ ㅋ ㅌ ㅍ ㅎ
- **중성(21):** ㅏ ㅐ ㅑ ㅒ ㅓ ㅔ ㅕ ㅖ ㅗ ㅘ ㅙ ㅚ ㅛ ㅜ ㅝ ㅞ ㅟ ㅠ ㅡ ㅢ ㅣ
- **종성(28):** (없음) ㄱ ㄲ ㄳ ㄴ ㄵ ㄶ ㄷ ㄹ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅁ ㅂ ㅄ ㅅ ㅆ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ

### 2-2. 음절 분해·조합

```
code   = 음절의 유니코드 (가 U+AC00 ~ 힣 U+D7A3)
offset = code - 0xAC00
cho    = floor(offset / 588)          // 0~18
jung   = floor((offset % 588) / 28)   // 0~20
jong   = offset % 28                  // 0~27, 0 = 받침 없음
조합    = 0xAC00 + (cho * 21 + jung) * 28 + jong
```

완성형 한글 음절이 아닌 글자(영문, 숫자, 공백, 낱자 ㄱ·ㅏ 등)는 분해 결과가 "없음"이어야 한다. 예외를 던지지 않는다.

### 2-3. 3D 좌표

```
GAP = 3
음절 (cho, jung, jong) 의 교차점 = (cho * GAP, jung * GAP, jong * GAP)
초성 포탄 목표 = (cho * GAP, 0, 0)
중성 포탄 목표 = (0, jung * GAP, 0)
종성 포탄 목표 = (0, 0, jong * GAP)
```

### 2-4. 낱자(1단계용) 처리

1단계는 자음·모음을 단독으로 입력한다. 낱자는 호환용 자모(U+3131~U+318E)로 들어온다.

- 자음 낱자 → 초성 인덱스로 바꿔 X축만 쏜다. 초성으로 쓸 수 없는 겹받침(ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ)은 1단계 출제 대상에서 뺀다.
- 모음 낱자 → 중성 인덱스로 바꿔 Y축만 쏜다.

## 3. 게임 모드

### 3-1. KFall (한글낙하) — 1~4단계

```
단어가 위에서 떨어진다
  → 플레이어가 단어를 타이핑하고 Enter
  → 낙하 중인 단어 중 입력과 정확히 같은 단어를 찾는다
  → 첫 글자를 분해해 초·중·종성 좌표 계산
  → 캐논 3기가 각 축 좌표로 이동해 곡선 포탄 발사
  → 단어 위치에서 폭발 + 영어 뜻 표시
```

| 단계 | 출제 | 기본 낙하속도 (u/s) | 최대 동시 등장 |
|---|---|---|---|
| 1 | 자음·모음 낱자 | 0.36 | 1 |
| 2 | 받침 없는 음절 (초성+중성) | 0.47 | 2 |
| 3 | 받침 있는 음절 (초성+중성+종성) | 0.66 | 3 |
| 4 | 단어 (2음절 이상) | 0.99 | 4 |

- **클리어:** 50킬 또는 10분 생존
- **실패:** 단어가 바닥에 5번 닿음
- **속도 상승:** 1레벨에서 시작해 1분마다 +1, 최대 9레벨. `속도 = 기본속도 × 1.2^(레벨-1)`.
- **반응속도 점수 배율** (단어가 나타난 뒤 격파까지 걸린 시간):

  | 시간 | ≤1초 | ≤2초 | ≤3초 | ≤5초 | ≤10초 | 그 이상 |
  |---|---|---|---|---|---|---|
  | 배율 | 3.0 | 2.5 | 2.0 | 1.5 | 1.2 | 1.0 |

- **콤보:** 5콤보마다 +50% (5콤보 ×1.5, 10콤보 ×2.0 …). 틀린 입력이나 바닥 도달 시 콤보 0.
- **틀린 입력:** 입력한 글자의 자모 좌표로 빗나가는 포탄을 쏘고 버저음.
- **힌트:** 입력 중인 글자로 시작하는 낙하 단어를 강조 표시.

- **단어 격파 점수:** `round(100 × 반응배율 × 콤보배율)`.

### 3-2. KShell (한글포격) — 5단계

```
3D 공간에 목표 구체(음절)가 나타난다
  → 다이얼 3개를 돌려 조준: X(초성) · Y(중성) · Z(종성)
  → 발사: 초성·중성·종성 포탄이 각각 따로 날아간다
  → 축마다 오차 = |다이얼 인덱스 − 목표 인덱스|
```

| 축별 오차 | 판정 | 결과 |
|---|---|---|
| 0 | 직격 | 그 축의 음소 HP 감소, 점수 `200 + floor(개별타이머 남은 초) × 10` (개별 타이머가 없으면 200점) |
| 1~3 | 근접 | 점수 `max(10, floor(60/오차))` |
| 4 이상 | 빗나감 | 없음 |

- 초성·중성·종성 HP가 모두 0이 되면 목표 격파 + 큰 폭발.
- 개별 타이머가 0이 되면 그 목표는 사라지고 격파로 치지 않는다.
- **클리어 보너스:** `floor(미션 남은 초) × 10`.
- **긴박 연출:** 개별 타이머 30초 미만 또는 미션 60초 미만이면 목표가 맥동한다.

| 스테이지 | 목표 격파 수 | 제한 시간 | 개별 타이머 | 최대 동시 목표 |
|---|---|---|---|---|
| 1 | 5 | 10분 | 없음 | 5 (처음에 모두 등장) |
| 2 | 8 | 8분 | 120초 | 4 (자동 보충) |
| 3 | 12 | 10분 | 90초 | 5 (자동 보충) |

> 미정: 음소별 HP 값. 처음 구현에서는 축마다 1로 둔다(직격 한 번에 그 축 완료).

## 4. 단어 데이터와 카테고리

- 단어 하나 = `{ word: 한글, meaning: 영어 뜻, stage: 1~4 }`
- 카테고리: DB 전체, 한국음식, 한국여행, 한국지명, 한국교통, 한국의 산, 기초한국어, 몸과 마음, K-Wave, 한국 속담, 사용자 정의
- 선택한 카테고리의 단어가 모든 단계에 공통으로 쓰인다(단계 조건에 맞는 것만 출제).
- **사용자 정의:** CSV 파일(`단어,영어뜻`)을 불러와 교육 현장용 단어세트로 쓴다. 형식이 틀린 줄은 건너뛰고 몇 줄을 건너뛰었는지 알려 준다.
- 원본 데이터(400+ 단어)는 Unity 프로젝트 `Core/WordDatabase.cs`, `Core/CategoryDatabase.cs`에 있다. 옮길 때 **사람이 파일을 제공**해야 한다(Fusion은 프로젝트 밖 파일을 읽지 않는다).

## 5. 화면 흐름

```
시작
 └─ 카테고리 선택
     └─ 모드·단계 선택
         ├─ KFall: 3D 월드 + HUD + 입력창
         │    ├─ 클리어 → 결과 화면 → 다음 단계 / 메뉴
         │    └─ 게임 오버 → 결과 화면 → 메뉴
         └─ KShell: 3D 월드 + 다이얼 3개 + 미션 HUD
              ├─ 미션 클리어 → 결과 화면 → 다음 스테이지
              └─ 미션 실패 → 재시도 / 메뉴
```

- **HUD:** 점수, 콤보, 단계명, 미스 표시 5칸, 힌트, KShell 판정 메시지, 미션 진행(격파 수·타이머)
- **최고점수:** 단계별로 브라우저 `localStorage`에 저장. 저장이 안 되는 환경에서도 게임은 정상 동작해야 한다.
- **모바일:** 화면 키보드로 한글 입력. 한글 조합 중(IME composition)에는 판정하지 않고, 입력이 확정된 뒤(Enter) 판정한다.

## 6. 3D 월드

- 배경 `#060810`, 카메라 시야각 50°, 기본 위치 (70, 55, 70) → (5, 8, 5)를 바라봄, 부드럽게 따라감
- X·Y·Z 축, 격자선, 자모 라벨 노드, 바닥, 원거리 별
- 캐논 3기(축별 색), 곡선(베지어) 포탄 + 꼬리, 폭발 파티클 + 영어 뜻 떠오르는 글자
- 포탄·파티클은 재사용(오브젝트 풀)으로 만든다.

## 7. 사운드

외부 파일 없이 Web Audio로 합성한다: 발사, 폭발, 직격, 성공, 실패, 버저. 브라우저 정책상 첫 사용자 입력 뒤에 오디오를 켠다.

## 8. 코드 구조와 개발 규칙 (Fusion 작업 규칙)

```
src/core/    순수 규칙 — 한글 분해, 좌표, 점수, 단계 설정, 단어 데이터. DOM·three·브라우저 API 사용 금지.
src/game/    게임 상태 진행 — KFall, KShell 상태 기계. 시간은 인자로 받는다(Date.now() 직접 호출 금지).
src/render/  three.js 화면 — 격자, 캐논, 포탄, 폭발, 카메라.
src/ui/      DOM UI — 메뉴, HUD, 입력창, 다이얼, 결과 화면.
tests/       vitest 테스트. tests/**/*.test.ts
```

1. **규칙은 `src/core`, `src/game`에 두고 반드시 테스트한다.** 화면 코드(`render`, `ui`)에 게임 규칙을 넣지 않는다.
2. **시간과 난수는 주입한다.** 테스트에서 같은 결과가 나오도록 `now`, `random`을 인자로 받는다.
3. **의존성 추가 금지.** `package.json`은 사람이 관리한다. 지금 있는 것: `three`, `typescript`, `vite`, `vitest`, `@types/three`.
4. **검증 명령:** `npm test` (타입 검사 `tsc --noEmit` + `vitest run`). 실패하면 PASS가 아니다.
5. 화면에 보이는 글은 한국어, 단어 뜻은 영어.
6. 이 문서와 코드가 다르면 문서가 기준이다. 문서를 바꿔야 하면 코드와 같은 작업에서 함께 고친다.
